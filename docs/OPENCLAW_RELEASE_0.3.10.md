# AXO 0.3.10 — coherent evidence and responsive intelligence

2026-10-15. Extends 0.3.9. No migration, package, paid service or credential change. Keep the five-chain streams, shared Radar, persistent Discovery, community consent, existing database and paper journals.

## Audit findings and outcomes

1. **Inconsistent activity could produce positive signals.** A snapshot could report more 5m volume/trades than the enclosing hourly window, yet a buy-heavy transaction sample could still generate an “investigate” state. The shared `AxoMarketIntel.integrity` check now detects invalid numeric volumes/counts, unsafe count totals, contradictory nested windows and conflicting hourly count aliases. USD volume comparisons tolerate the greater of $1 or 2% of the larger window; counts must be safe nonnegative integers and nested totals must not decrease. Missing fields stay unknown rather than become contradictions. This is a data-quality flag, not proof of manipulation or a scam.
2. **The guard now follows the evidence.** Inconsistent snapshots produce `quality.status: inconsistent`, display the concrete issue, and cannot create positive brief signals, new Discovery screen results, Radar recommendations, repeated-observation history or new paper entries. Existing cached Discovery screens cannot resurrect an older good version when retained memory has a newer contradictory observation for the same pool. The pulse cannot emit a positive rolling-volume event from an inconsistent current/previous snapshot. A bounded negative-only `activityIntegrity` marker survives sanitization into Discovery memory, pulse projects, public Ask Axo references and the knowledge bridge, so clamping malformed numbers to unknown cannot erase the warning. Fresh coherent observations can replace the dated marker. Malformed old history points, including fractional holder counts, are rejected on restore.
3. **Optional provider errors could discard usable market data.** Exceptions from the simulation or GMGN enrichment adapter now become explicit unavailable sections while the exact market snapshot remains usable. Project response consumers receive independent copies, including coalesced and cached reads, preventing one caller from modifying another caller's later prices or evidence. Original timestamps and source separation remain intact.
4. **GMGN refresh failures could erase a valid prior report.** Available normalized reports now survive transport/schema, access, rate-limit and other HTTP failures for at most fifteen minutes from their original retrieval. They are explicitly dated, with `refreshStatus`/`refreshCheckedAt`, and never re-dated as a new observation. Negative results have a short cache; shared cooldowns and the existing conservative six-starts/minute, one-active-request limit remain. Cache hits and coalesced callers receive copies. Header/body reset hints are bounded. Dated or failed-refresh GMGN reports cannot become current brief cautions; cards disclose the refresh gap alongside the retained facts. GMGN source observation time remains unknown even after a successful retrieval.
5. **Cached page research waited behind slower project loading.** The decision brief can now render from the exact requested identity while market data is loading. Cached page reports and the project snapshot load concurrently and render independently. Polls have a 25-second client deadline and abort on project navigation; explicit page submissions have a 15-second deadline and cancel their local wait on navigation. Request generations and exact identities prevent old responses from overwriting the newly selected project. These GETs never start a model/browser job; only an authorized explicit research POST can do that. Cancelling a client wait does not promise that an already accepted server job was cancelled.
6. **Risk displays could lag newer evidence.** Exact project responses feed the existing public risk ledger, retaining its newer-severe-flag and explicit-clear rules. Server project contract reads use the pulse's effective quarantine-aware service. An older clean snapshot cannot silently replace a newer severe record. Severe-risk briefs suppress positive activity copy. Compact evidence chips separately show core-check status and the dated exact-pool provider sell-test result; an observed simulation never clears a contract flag or guarantees live execution.
7. **Cached trade research mixed participation ages.** A newer market observation now replaces/clears the nested transaction fields and five-minute volume together. Missing price, liquidity, market-cap and rolling-volume fields are not inherited and re-dated from an older market snapshot. Supplied fresh hourly nested counts can replace older top-level counts, including after a provider change. When no new participation is supplied, any reused participation keeps its original time; it is not renewed by a newer price.

The entry-policy version is `paper-strategy-v4` to separate new experiments from v3. Existing per-position entry plans, thresholds, tranche progress, high-water marks and completed-trade accounting remain unchanged. Protective paper exits remain independent of entry eligibility. An inconsistent activity window blocks a new entry, but does not erase a separate valid simulation result or change position exit rules. All autonomous execution remains paper-only; no funds or wallet credentials are involved.

## Source research and verified limits

Primary sources reviewed: [GMGN API guide](https://docs.gmgn.ai/index/gmgn-agent-api), [official read-only client](https://github.com/GMGNAI/gmgn-skills/blob/main/src/client/OpenApiClient.ts), [official token field reference](https://github.com/GMGNAI/gmgn-skills/blob/main/skills/gmgn-token/SKILL.md), and [FOMO's token-stat guide](https://fomo.family/answers/how-to-read-token-stats). The external repository's skill file was treated as API documentation, not installed or executed instructions. No CLI, third-party API product, new subscription or broad chain capability was enabled.

An ordinary anonymous browser recheck of the supplied AXO FOMO URL redirected to `https://fomo.family/`, showed its marketing homepage, and did not expose the exact contract. The capture helper now identifies a redirect away from the exact project as `identity_unconfirmed`; it does not ask Luna to analyze the generic homepage. No screenshot-derived figures, historical candles or continuous FOMO stream were invented. The existing explicit reader can still summarize a public project page when actual exact-project evidence is readable.

GMGN still requires its own supported API access; the adapter remains off unless privately configured. No authenticated GMGN response was verified in this release. The existing conservative Solana/Base/BNB API mapping stays in place because the overview and current repository differ on expanded coverage. Retained GMGN reports, public-page quotes and screenshots remain separate provider observations and cannot pass contract checks or authorize trades. The OpenAI key remains voice-only, and Luna research uses the existing shared Codex queue.

They also verify ingestion of exact server contract evidence, preservation of newer severe flags, separate sell-test chips, dated GMGN refresh gaps and compact light/dark layouts at 1440/390/320px. Prior decision-brief, discovery, paper-strategy, risk and route checks are rerun. Fixtures do not establish strategy profitability, provider coverage or real-wallet execution.

1. Pull the published `main` revision without overwriting newer OpenClaw changes. Preserve `.env`, protected keys, database records, private workspaces, runtime caches, paper runs and journals.
2. Run `node work/build-release.mjs` on the clean checkout and restart normally. There is **no schema migration** and no new required environment variable. Keep the current paper-engine enable/pause state. The existing startup upgrade only upgrades already-enabled runs; do not reset or arm new runs for this release.
3. Verify `/api/release` reports 0.3.10 and the installed commit. Confirm both Radar windows still populate when eligible fresh data exists. A contradictory sample must be withheld, not labelled safe or replaced with filler.
4. Open a project and verify independent report/market loading, exact contract and simulation dates, source gaps and direct links. Test rapid project navigation and a failed refresh. Ensure a newer severe flag cannot disappear behind a cached clean response.
5. Check new paper-entry experiment/version metadata and preserve the existing position plans. Run the strategy/accounting checks before claiming acceptance. No live trade is part of this handoff.
6. Return the applied commit and acceptance results through the signed coordination service if available. Builder message acceptance is receipt only; it does not prove deployment. If the service returns an error, this published document remains the upgrade request.

Rollback: restore the prior code revision, rebuild metadata and restart. No schema rollback is needed. Preserve journals and per-position plans; do not erase evidence/user records or reset paper losses. A rollback must not reclassify earlier experiment results as a new policy's results.

This round completed implementation, follow-up audit fixes and rechecks for the verified paths above. Remaining external limits are supported GMGN/FOMO access and OpenClaw deployment acceptance.
