# AXO 0.3.11 — easier navigation and Discovery filters

2026-10-15. Extends 0.3.10 and preserves OpenClaw's retained-stream continuity update. No migration, new dependency, credential or provider change.

## UX audit and implemented improvements

- **Results were crowded below controls on phones.** At 390×844, the observed first-board position was about 794px. Discovery's extra numeric ranges and evidence requirements now sit inside a collapsed More filters section; chain/category choices remain visible. The mobile shortcut strip scrolls horizontally and retains all 21 streams. Existing settings share the saved-shortcut row. An ordinary live-data check put the first board at about 642px, around 150px earlier; exact placement depends on current status text and active chips. The first-results position is also checked with deterministic fixtures. This is progressive disclosure, not removal of filters or navigation.
- **Icons alone were hard to navigate.** A small current-stream label, Back button and Find stream search now accompany the existing shortcuts. Find stream opens a native modal dialog via its button or Ctrl/Command K; it searches common streams, Profile and saved shortcuts. Arrow keys and Enter select existing routes, Escape closes, and focus returns to the opener. Account/Portfolio/Credits/wallet/build controls remain. Back restores the prior scroll position within the currently available layout in this page session; it does not promise persistent scroll history after reload or before asynchronous content exists.
- **Numeric filtering was easy to misread or accidentally clear.** Amount fields now accept 50k, 1m and properly grouped 100,000, with finite nonnegative bounds and scores limited to 100. A minimum greater than its maximum is explained immediately. Invalid draft text stays on screen through background renders, but does not replace or persist the last valid criteria. Users can correct either bound or discard the draft. Older saved contradictory ranges receive an explicit recovery explanation. Small phones use full-width field pairs with 16px text and larger input targets.
- **Active criteria and empty results needed a way out.** Nondefault ranges and evidence requirements appear as removable chips even while More filters is closed. Reset and individual removal have an in-session Undo filter change. Zero categories/chains have direct recovery actions; zero matches with extra constraints offer Clear extra filters, and a source-only empty result offers Retry collection. Clearing extra filters retains the chosen categories/chains and restores the existing default $1k minimum liquidity. Reset clears the Sniper/Degen preset identifier as well as the criteria, so its label cannot claim a preset that is no longer selected. Existing freshness, severe-risk exclusion and the separate explicit Review unchecked control are not relaxed.

## Follow-up audit fixes

The first browser pass caught a phone settings panel covering its own summary button. Panels now position from the actual button's viewport bounds, choose available space above/below, and update on scroll/resize; off-screen anchors close the panel. Existing settings nodes and listeners are moved intact, including after saved-shortcut rerenders. Stream-icon arrow navigation excludes hidden and disabled shortcuts and does not capture arrows inside the relocated settings panel. Range drafts are protected in both the original Discovery and later score renderers, so live updates cannot erase an invalid value before the user corrects it.

The design review used the [W3C modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) for focus, keyboard dismissal and background isolation, and [W3C target-size guidance](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) for usable control sizes. This is scoped accessibility testing, not a claim of full WCAG certification. Native iOS/Android and screen-reader acceptance remain useful live follow-up checks.

## Verification

`npm run test:usability` checks amount syntax, exact formatting, invalid ranges and chips, then exercises the real dashboard with synthetic public project evidence. Browser cases cover mobile result placement, all common shortcuts and account buttons, finder keyboard navigation and focus return, persisted valid filters, rejected draft persistence, live-render draft retention, correction from the other bound, remove/undo/reset, old saved range recovery, zero-chain/category recovery, Back scroll restoration, preserved settings node identity and settings dismissal, and readable 1440/390/320px layouts in both themes.

Regression checks cover the 3-second reading anchor with updates around it, retained Discovery before slow providers, five-chain presets, rich Discovery rows, compact feedback controls, stream-memory restore, shared Radar across streams/users and both time windows, independent project/page evidence loading, decision briefs, private-user isolation, stream schema, and all 89 served dashboard scripts. Two older browser checks now honor AXO_BROWSER_CHANNEL instead of requiring Edge, allowing the installed Chrome runtime to run them. Fixtures do not establish live provider coverage, investment safety, profits or wallet execution.

## OpenClaw install and acceptance

1. Pull the published main revision, preserving newer OpenClaw commits and all private configuration, keys, database records, cached source evidence, user workspaces and paper journals. The concurrent retained-stream continuity change is included.
2. Run `node work/build-release.mjs` on the clean checkout and restart the dashboard normally. No schema migration, environment variable or package install is added. Preserve the paper engine's enable/pause state and existing position plans; this release does not arm trading or change entries/exits.
3. Check `/api/release` shows version 0.3.11 and the installed revision. Verify `/discovery-filters.js` and `/usability.js` return JavaScript (89 page script routes total). If old assets appear, perform a fresh page load.
4. At phone width, open Discovery: categories/chains and first results should be visible sooner, with More filters collapsed. Open it and type 50k/1m; enter an invalid reversed range and confirm the previous valid results stay selected. Correct/discard it, remove a chip, Undo, Reset, and try an empty category/chain selection.
5. Use Find stream for Profile, a chain and a saved shortcut. Check keyboard focus/Escape, Back, the horizontal stream icons, all five settings menus, and header wallet/Profile/Portfolio/Credits. Verify menus do not cover their own buttons at 320/390px. The shared Radar must retain its selection/scrolling when changing streams.
6. Return the applied commit and acceptance results over signed coordination. A message acknowledgment is receipt only, not installation. If coordination is unavailable, this published handoff remains the upgrade request.

Rollback: restore the prior code revision, rebuild metadata and restart. No database rollback. Keep user filters/workspaces and paper history. The new filter controls use the existing numeric saved format, so older valid settings remain readable.

This implementation, audit, correction and recheck round addresses the verified UX bottlenecks above. Further UX improvement should be guided by live task completion and device feedback; the release does not claim that every possible improvement is exhausted.
