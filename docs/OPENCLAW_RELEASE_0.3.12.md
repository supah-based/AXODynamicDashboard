# AXO 0.3.12 — easier project screening and Watchlist workflows

2026-10-15. Extends 0.3.11. No migration, dependency, credential, paid service or execution-policy change.

## Audit findings and improvements

1. **Screening required too much scrolling.** A representative mobile fixture produced 23 project cards; its decision brief was roughly 4,000px down and Risk & origin roughly 5,500px down. The project focus area now offers direct Decision, Risk, Chart and Activity actions plus a named menu of every currently rendered section. It replaces the generic context-tile block in this view. Jumps focus the actual section heading and scroll it below the fixed Radar. All existing screening cards remain available. Default ordering puts the exact project anchor first, followed by the decision brief, risk, chart and activity. Explicit pins, active manual ordering and requested layouts retain precedence. No new signal, profit estimate or safety conclusion is calculated by this navigation.
2. **Watchlist had no fast way to isolate a follow.** The focus area now searches saved names, tickers and contracts, with chain, active-alert and data-gap filters. The compact overview and corresponding project cards use the same selection. Previously a chain-specific Watchlist could show a filtered set of cards beside a summary containing all chains; that inconsistency is corrected. Counts state how many of the total saved follows match. Filtering is a local view operation and does not remove follows, discard warnings or turn follows into holdings. Existing contextual news/social logic may follow the selected Watchlist scope through its normal polling.
3. **Empty results needed a next step.** A filtered-out list says that filters excluded the follows and offers Clear filters; an actually empty Watchlist offers Find projects, using the existing Discovery route and its screening policy. A new Refresh visible control reuses the existing exact-project loader for the matching follows. It disables while matching requests are in progress and shows a refreshing count. Missing or dated observations retain their original labels; completion is not a promise that every source was available.
4. **Accidental removals had no local recovery.** A removal now offers a 30-second Undo in Watchlist controls. It restores only that exact follow at its former position, without replacing intervening follows or duplicating a follow already added back. Original evidence timestamps are retained. The pending Undo and transient search/mode state belong to the current wallet/account generation; a switch clears them, including visible text in a still-focused field. Nothing is restored into another identity. The existing private Watchlist save path is reused.

## Follow-up audit corrections

- Explicit refresh previously bypassed one UI cache but could still hit the two-minute transport cache. The existing loader now forwards its force option; the adapter rechecks the server for explicit refresh while still coalescing identical in-flight requests. Server cache policy and source observation timestamps remain authoritative; refresh does not force an upstream provider to produce a new observation.
- The transport cache previously keyed only chain/token/detail. It now includes the exact selected pool, preserving Solana case and normalizing EVM case. Opening another pool of the same contract cannot receive the first pool's cached response. The browser test opens a second pool with a distinct fixture price and checks that the new pool is actually selected.
- Undo waits until the existing removal handler has completed before offering recovery. Unchanged status messages and the Undo node are preserved during live renders so repeated polling does not repeatedly announce the same count or remove keyboard focus.
- Project jumps expose named controls and focus the chosen heading. Scroll padding reserves space for the Radar and Ask Axo overlay. This follows the intent of [W3C focus-not-obscured guidance](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html) and [status-message guidance](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html); it is scoped testing, not full accessibility certification.

Regression checks cover existing compact Watchlist values, timestamps, source controls, exact DEX links, sorting, removal/reload storage and empty state; prior Discovery/navigation UX; independent project/page research loading and newer risk evidence; decision briefs; the three-second reading anchor and updates around it; global Radar continuity and both time windows; private-user isolation, stream schema and all 90 script routes. The older Watchlist check now tests its intentional shared chain scope, honors AXO_BROWSER_CHANNEL, and waits for the app DOM instead of unrelated external-media load completion. Browser assertions still verify the actual interaction outcomes. No wallet signing, real trade or model call is required for these fixtures.

Check that the project anchor remains first, all detail cards remain available, pins still work and focus is visible above overlays. Change projects rapidly and test another pool of the same token.
5. In Watchlist, search for a saved ticker or contract, combine chain and alert/data-gap modes, clear filters, refresh the matching follows and inspect the retained observation dates. Message acceptance is receipt only; installation requires an applied revision and successful checks. If coordination is unavailable, this published handoff remains the upgrade request.

Rollback: restore the prior code revision, rebuild metadata and restart. No schema rollback. Keep private follows, source records and paper history. Search/mode/Undo are transient view state; the existing saved Watchlist format remains unchanged.
