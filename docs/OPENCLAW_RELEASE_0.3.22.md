# AXO 0.3.22 Trading Desk and five-chain audit

The production audit on November 23, 2026 inspected release 0.3.21 on desktop and at 390 px, the live coverage report, and all five initial chain feeds. It found 31 of 52 sampled source paths available. Robinhood had one recent sampled pool. Arc had nine recent observations and zero complete five-minute trade readings in that pass. The home stream had useful individual research cards, but finding comparable candidates and checking entry and exit evidence took several separate views.

## Research and changes

- **Find and compare.** Home starts with five-chain screening for active markets, accelerating activity, new pools, pullback patterns, and followed tokens. Screens show measured reasons and let traders compare up to three exact pools. The disjoint five-minute and prior 55-minute rates distinguish acceleration from a high rolling total. All-chains screens reserve a first result for each chain with a qualifying pool. Filters and partial coverage stay visible. The browsing flow is based on the lifecycle, filter, and inspection patterns documented by [Axiom Pulse](https://docs.axiom.trade/axiom/finding-tokens/pulse) and [GMGN New Pair](https://docs.gmgn.ai/index/new-pair).
- **Inspect and follow.** Pool details expose market cap, FDV, USD liquidity, turnover, price windows, dated holder evidence, exact addresses, and any reported risk flags. Unique traders come from a provider count. Existing Watchlist and alerts accept the selected contract and pool, and alert checks run while the dashboard is visible. The source links and research views remain reachable from the desk. [GMGN token-page workflow](https://docs.gmgn.ai/index/token-page-chart-multicharts-activity-trading-system), [GeckoTerminal API](https://api.geckoterminal.com/docs/index.html).
- **Check entry and exit.** The desk keeps buy-and-sell simulation, route quotes, technical entry context, and missing evidence visible as separate observations. Quotes expire and may cover a token route at a test size. Review swap opens the existing manual swap form. Both the source context and a quote for the intended trade size matter. [Uniswap on price impact and slippage](https://support.uniswap.org/hc/en-us/articles/8643794102669-Price-Impact-vs-Price-Slippage).
- **Collect across all five networks.** Each pass prioritizes the first top and new GeckoTerminal pages, including the verified Arc network ID, then uses current exact-contract DEX Screener and available native launchpad evidence for gaps. Thin BNB Chain, Arc, and Robinhood samples can use chain-matched DEX search rows, clearly labeled as search coverage. A shared rotation continues without an open browser. Pool age and provider times remain attached to the original data. Arc chart lookup accepts exact 32-byte pool IDs. [GeckoTerminal Arc markets](https://www.geckoterminal.com/arc/pools), [DEX Screener API](https://docs.dexscreener.com/api/reference).
- **Read on-chain facts.** An explicit read from the selected pool checks its token's bytecode and reported supply on EVM networks, or its initialized SPL mint, supply, and mint and freeze authority on Solana. The RPC chain ID or genesis hash is validated. On-chain checks show the provider, block or slot, and when it was read. [Alchemy Chain API networks](https://www.alchemy.com/docs/reference/node-supported-chains), [Solana RPC](https://solana.com/docs/rpc/http).

The desk's screens prioritize research observations. Holder concentration can include exchanges, burn accounts, pools, and locked tokens. A liquidity change in USD can include price movement. Token supply, contract bytecode, and RPC availability are separate from market depth, transfer permissions, and sellability.

## Validation and deployment

- A live collector pass returned 112 fresh exact-token representatives, with complete five-minute trade counts on each chain. That sample included 20 on Solana, 29 on Base, 30 on BNB Chain, 24 on Robinhood, and 9 on Arc. Robinhood and Arc used fallback coverage and had no unique-trader figures in that pass. Arc's 32-byte candle validation passed with fixtures, and the live candle request was limited by provider cooldown.
- Run `pnpm run test:trading-desk`. The Chrome workflow covers filtering, comparison, exact-pool entry and exit receipts and quote expiry, on-chain identity, Watchlist, alert creation, manual swap review, chain pagination, and persistence. Fixtures check 320, 390, and 1440 px widths.
- Use the existing protected server configuration for `AXO_ALCHEMY_API_KEY`. RPC credentials travel in the Authorization header. After enabling BNB Chain and Arc, the credential verified mainnet RPC on all five chains. Exact ERC-20 Token API metadata and balance reads passed on Base, BNB Chain, Robinhood, and Arc. The on-chain check shows Alchemy's name and ticker separately from the contract's block-pinned decimals and supply. The private-preview market API still returned HTTP 401 in the recheck. [Alchemy header authentication](https://www.alchemy.com/docs/how-to-use-api-keys-in-http-headers), [Alchemy Token API](https://www.alchemy.com/docs/reference/token-api-overview), [Alchemy Trading API coverage](https://www.alchemy.com/docs/data/trading-api/networks-and-conventions).
- Deploy through the existing build and restart process. Keep the current server secrets, runtime state, signed wallet flows, and provider allowances. This release needs no new dependency or database migration. Verify the installed commit and version at `/api/release`, then confirm the desk's `/api/trading-desk` describes each chain and distinguishes partial from current pool coverage.
