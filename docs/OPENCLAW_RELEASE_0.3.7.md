# AXO 0.3.7 — retained Discovery and source-grounded activity briefs

Date: 2026-10-15. Additive to `b4d93376d75a178d8e9bb44dd40f6622535c1aa0` (0.3.6). Pull current `main`; preserve concurrent OpenClaw changes and the existing database, runtime files, paper journal, wallet connector and authentication. No new dependency or database migration is required.

## What users receive

- Discovery opens from a shared retained catalog before slow provider requests finish. It combines recent finds, current activity and explicitly shared community interest, while the user's existing chain/category/numeric filters and risk admission remain in effect. Compact cues explain “New to Axo”, “Community interest” and “Activity rising”. New evidence is read every 15 seconds while Discovery is visible; the server collects cached public observations every 30 seconds and after main feed refreshes. These are refresh intervals, not guaranteed provider latency.
- Up to 120 exact project records survive restarts for seven days, with fair capacity across the five dashboard chains. An original market observation is never redated by a cache read. Records older than 15 minutes move to expandable dated history rather than masquerading as current opportunities. Severe source flags are excluded from both current results and history; private watchlists and individual holdings are not imported into the public catalog. The existing “Review unchecked” control remains the explicit way to inspect incomplete checks.
- The existing opted-in community service supplies aggregated cohorts of at least three signed wallets. Its bonus is capped at eight points and expires when the aggregate is stale/unavailable. Those counts are not evidence of unique people or investment quality. Up to two qualifying community tokens per minute can request exact-token market enrichment when absent/stale; per-token retry cooldown is five minutes. No private user data or community members are persisted in Discovery memory.
- Cards reveal with a short opacity/scale change at their final packed location. Neighbouring cards move aside; new cards no longer travel from the top. Reduced motion disables this motion. The existing three-second hover, focus/touch reading hold and surrounding updates remain intact.
- GMGN token links sit beside DEXScreener and Matcha. They preserve the exact chain and contract. Link availability does not establish that GMGN indexes every dashboard chain/token.
- The project decision brief presents five-minute volume, transaction count, recent activity pace, data quality, cautions and the next research action. Pace compares the latest five minutes with the average five-minute rate over the *preceding* 55 minutes, not an overlapping hour. An activity lead needs at least ten five-minute transactions and $5k hourly volume. Buy counts are not unique buyers or net inflows. Missing denominators/counts remain unknown; large extension, thin liquidity and excessive turnover create cautions.

## Collection and evidence changes

1. DEXScreener collection uses latest profiles, recent profile updates and reported community takeovers, then at most one batch of ten exact contracts per chain per pass. This replaces individual lookups and admits older projects for later classification. A listing/takeover claim is an attention lead, not verified ownership, launch time or organic demand. Partial source failures remain visible; retained observations preserve their dates.
2. Exact-pool market merge chooses the latest original snapshot; provider preference only breaks timestamp ties. Financial fields are kept atomic. An absent market cap is never filled from another snapshot or replaced with FDV. Fresh, closely timed provider price disagreements above 20% create a conflict and block strategy entries; provider agreement is not independent verification.
3. Pool changes reset the activity comparison baseline. A switch to a deeper pool must not fabricate liquidity/volume growth. Cached project briefs also re-evaluate freshness and current risk.
4. An optional official GMGN Agent API adapter reads only `GET /v1/token/info` from `https://openapi.gmgn.ai`, using `X-APIKEY`. It supports the conservatively documented Solana/Base/BSC subset, one concurrent read, six starts/minute, two-minute bounded caches and provider cooldowns. Only whitelisted token-level counts, concentration, price and liquidity are retained. Retrieval time does not establish source observation time. No wallet list, trading key, signed order or account access is used. The adapter is OFF unless an operator deliberately configures both `AXO_GMGN_DATA_ENABLED=1` and `GMGN_API_KEY` privately. No account was created and no authenticated live GMGN response was verified in this release.

## Public-page and screenshot research

The project brief offers explicit “Read GMGN page” / “Read FOMO page” actions. These require the existing verified `ask` access and same-origin request controls. They do not run automatically for visitors. A fresh isolated browser reads only an exact allowlisted chain/contract page, without saved authentication or wallet state. Access challenges are not bypassed. Captures, text and image input are bounded; at most four jobs queue, capture/model work is serialized, and waiting jobs expire after two minutes. The existing shared Luna queue and subscription perform interpretation; the OpenAI audio key remains voice-only.

Only text figures with a matching literal source quote survive normalization. Screenshot-only figures are labelled unverified visual estimates. A static token share image is never promoted to chart analysis. Reports have retrieval dates and explicit limitations, remain bounded in process memory, and cannot pass risk checks, supply candle indicators or authorize trading. Screenshots/raw page bodies are not committed or stored in the database. GET reads do not start work; errors are cached briefly and remain explicit.

## Audit findings resolved and remaining limits

Audit/recheck resolved the older snapshot overriding newer quotes, financial-field mixing, cross-pool comparison baselines, unbounded negative enrichment caches, loss of Discovery across restart, a scheduler/memory route collision, an older UI sorter overriding the new rank, and overly broad initial card movement. Fair retention prevents a busy chain from consuming the whole catalog. These checks establish bounded correctness, not that every possible improvement is exhausted or that daily profits are achievable.

The trader remains automatic **paper** execution. Existing limits, conservative admission, fees, position accounting, protective exits, experiment separation and operator controls remain in effect. FOMO/GMGN access gaps and optional API terms, actual database deployment, production browser availability, signed OpenClaw acceptance and real-wallet testing are operator/live-environment verification tasks.
