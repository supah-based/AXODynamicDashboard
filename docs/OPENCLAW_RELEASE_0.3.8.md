# AXO 0.3.8 — continuous follow-up and comparable intelligence

2026-10-15. Extends 0.3.7 and preserves OpenClaw's `fcdc059` five-chain Sniper/Degen stream update. No new package, migration, credential or paid service is required. All execution remains paper-only.

## User outcome

Project decision briefs now show dated price, pool-liquidity and holder-count changes when comparable observations exist, plus whether activity pace persisted on three spaced snapshots. Thin evidence says “collecting”; provider/pool changes cannot manufacture a trend. Compact GMGN facts, when the optional API is configured, distinguish USD buy share from transaction counts and token-level concentration from exact-pool measurements. Cards show the market date and partial coverage, with specific gaps and a next step.

Home uses the latest available exact-pool market snapshot alongside the dated event that made a project relevant. It no longer keeps an old event's price while newer data is available. Stale market snapshots no longer produce positive “current” activity cues. Reading holds preserve the card while explicitly requested page findings update inside an existing live-result region. Both light/dark layouts are checked at 1440, 390 and 320 pixels.

Discovery now reserves up to four exact public projects per chain for a fifteen-minute follow-up cohort, refreshed within the existing ten-contract batch budget. The remaining slots continue rotating new profile/update/takeover leads. This supplies repeated observations instead of losing every candidate when it falls off a latest-project list. Cohorts use only the public catalog, not personal watchlists or wallet holdings; tokens older than an hour since their last observation do not enter a new cohort. Capacity is bounded and sampled, not exhaustive chain monitoring. Retained Sniper results use OpenClaw's existing criteria, alongside Degen/Swing/Blue Chip.

## Data and reliability

- The shared source collector has 128 pending slots, at most 24 waiting requests per provider and a 30-second admission/spacing wait. Expired waiters leave the queue cleanly. Provider-specific spacing/concurrency/minute budgets remain in force; GoPlus explicitly shares a 20-request/minute transport budget. HTTP 429 respects cooldowns; transient failures back off. Missing/denied endpoints have short per-request negative caching and do not stop unrelated endpoints as if the whole provider had failed. Provider bookkeeping is bounded and idle providers can be evicted.
- Cache identity includes normalized request-header hashes. Different credentials or API versions cannot join or reuse one another's responses. Only an allowlist of public GET header types may persist to the public database cache; consumers receive copies rather than mutable cache objects. Stale-memory fallback preserves original dates and is bounded like the existing database fallback. It does not turn a failed refresh into a new quote.
- Async source observation scopes carry original retrieval dates and partial/failure coverage through transformed top-level feeds. `receivedAt` remains the original oldest contributing read; `checkedAt` records the refresh attempt. Old feed-cache entries without these observation scopes are marked dated until refreshed. Exact-project responses also mark partial provider coverage. The cache identity change causes a one-time cold source-cache refill; retained Discovery remains available while it warms.
- The new observation book holds up to 80 exact pool/provider series, fairly retained across chains, with at most 16 spaced points each and a one-day horizon. It retains only public numeric observations, never user data. Comparisons need an original fresh timestamp, the same contract/pool/provider and a baseline 2–15 minutes earlier, chosen nearest five minutes. Activity persistence needs three samples separated by at least a minute. Holder changes need separately dated exact-token GoPlus counts; replaying one cached holder count is not growth. USD liquidity changes are not deposits/withdrawals, overlapping hourly volume is not independent acceleration, and wallet counts are not people.
- Persisted observation snapshots are bounded to 220 KB and use `$AXO_RUNTIME_DIR/axo-observation-book.json` plus the existing `axo_source_cache` table when enabled. Writes are debounced, local file replacement is atomic, and unavailable history leaves the main dashboard usable. No backfilled candles, fabricated history or screenshots enter these comparisons.
- Public-project bridge reads now preserve whitelisted five-minute volume, transaction counts and bounded dated quote comparisons. They still exclude private fields, risk-pass labels and execution authority. A provider switch resets pulse comparison baselines; a newer snapshot cannot be hidden merely because an older quote reported more liquidity.

The optional GMGN adapter now also whitelists documented USD volumes, buy/sell counts and bounded holder/developer/bot ratios. They remain separate provider reports with unknown source observation time. The configured API remains OFF by default; no live authenticated GMGN response was verified. The primary guide and current repository differ on expanded chain coverage, so this release does not silently broaden enabled API chains beyond the previously conservative Solana/Base/BNB subset. Provider labels and concentration do not establish identity or safety.

Public-page reports can now reuse the existing `axo_ai_cache` across restart instead of repeating model work. Only normalized summaries, bounded figure quotes, interpretation and original dates persist; raw page bodies/screenshots, prompts and keys do not. GET reads and Ask Axo context retrieval never launch a browser or a model. Negative database lookups are briefly cached. Failed refreshes preserve earlier dated findings and show a refresh gap. Explicit access challenges cool down the same source for five minutes; a missing token page alone does not block the entire source. Queue limits and holder/origin authorization remain intact.

Ask Axo's project context now includes the calculated brief, separate optional provider reports and cached public-page findings. Missing exact-pool context remains a gap rather than failing the whole question. Neither screenshots nor retrieved token-level figures can pass contract checks, calculate candle indicators or authorize a trade.

## Paper strategy and deployment

The paper entry policy now waits when a fresh, comparable observation shows at least a 25% drop in reported pool liquidity. This is a conservative entry filter, not a scam verdict or an automatic live exit. Current progression is reevaluated on cached research paths. Cached participation keeps its original timestamp and cannot cross providers. Strategy version is `paper-strategy-v3`, separating new-entry experiments; existing entry plans, journal history, exit thresholds and experiment fingerprints remain intact. Protective exits still run independently of entry admission and research availability. No guarantee of daily profits is made or tested.

Deployment:

1. Pull the published `main` revision without overwriting newer OpenClaw work. Preserve the database, private configuration and all runtime files/journals. Build release metadata on the clean checkout and restart normally.
2. Keep the existing database configuration; no migration is needed. Ensure the service owner can write the new observation cache. No `.env`, Builder key, screenshot or local probe should be copied from Git.
3. Check `/api/release` for 0.3.8 and the installed commit. `/api/intelligence-runtime` now includes `observations` and candidate `followUpCohorts`. Verify a selected cohort receives later source timestamps and builds spaced observations over time; cached reads alone must not increase confirmation.
4. Check transformed feed dates and partial coverage on `/api/dashboard`, compare a project before/after refresh, and test Sniper/Degen navigation. Keep incomplete checks behind the existing explicit review control. Verify signed community consent and privacy remain unchanged.
5. For page research, verify authorized action → queued result → dated report, then deny a refresh and confirm earlier findings remain dated. The existing installed-browser prerequisite and optional GMGN key policy from 0.3.7 still apply. No audio key is used for this work.

Audit passes resolved unbounded queue waits, header-insensitive caches, feed timestamp renewal, provider-switch comparisons, lack of repeat discovery collection, old Home quotes, stale positive cues, lost page reports, report refresh erasure, cached participation attribution and a reading hold that hid an explicitly requested result. Focused unit/integration/browser checks cover these paths plus existing privacy, risk admission, paper accounting, protective exits, strategy experiments and reading anchors. No further material issue remained in those checked paths after rechecks; this does not establish that all possible improvements are exhausted or that the strategies are profitable.

Rollback uses the prior known-good release and restart. The new caches are disposable public observations; do not erase the paper journal, private workspaces, existing project evidence or database to roll back this update.
