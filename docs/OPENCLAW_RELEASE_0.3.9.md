# AXO 0.3.9 — dependable Radar and time-window intelligence

2026-10-15. Extends 0.3.8; preserves the five-chain Sniper/Degen update, prior project observations, community consent, private workspace separation and paper strategies. No migration, dependency, secret or paid service is added.

## Findings and changes

The public live dashboard returned an empty Radar despite eleven projects with reported core checks in its wider screening sample. Some qualifying market observations were already 213 seconds old. DEXScreener Radar admission expires at 180 seconds, whereas collection ran in the slow global refresh group every three minutes, plus group/provider latency. A direct local API sample could contain five rows and a subsequent browser load already be empty. This was a timing and source-selection problem, not evidence that checks should be weakened.

- `axo-discovery-pump.mjs` runs one shared collection at startup and every 60 seconds independently of the slow global refresh group. Concurrent ticks join one promise; failures release the job for later attempts. Collection updates the existing feed, observation book and retained Discovery, then publishes the result. The exact-token batch cache lifetime is 60 seconds; profile and takeover seeds retain their 120-second cache. Existing provider spacing, request budgets, cooldowns, bounded batch sizes and stale-source dates remain intact. There is no fetch per visitor or mode switch.
- Radar combines the existing public Discovery catalog, pulse projects, chain pools, launchpad snapshots and candidate feed. Private watchlists, preferences, holdings and unpublished user activity are not inputs. Only whitelisted public fields leave the selector.
- Selection resolves the newest eligible-time exact-pool observation **before** evaluating financial thresholds. Newer low/unknown liquidity or zero volume therefore cannot be hidden by an older healthy version of the same pool. Each window then selects one representative pool per exact token from the current pool observations: deepest among observations no more than a minute older than the newest candidate, with deterministic identity ties. Financial values are not merged across pools/providers.
- Both windows require at least $50,000 pool liquidity and current complete required GoPlus core fields without reported flags. The **1h** selection requires at least $1,000 rolling hourly pool volume; **24h** requires at least $10,000 rolling daily pool volume. Each ranks by its own observed volume, up to ten tokens, and displays its own price-change field and sign. These are activity rankings, not predicted returns or safety guarantees. DEX observations still expire at three minutes, GeckoTerminal at fifteen minutes, and contract evidence at five minutes. Canonical stablecoins/native/wrapped-native assets, severe flags and unknown screening remain excluded.
- `/api/dashboard.projectRibbon` is schema version 2 with `modes.h1`, `modes.h24` and aggregate rejection diagnostics. The top-level `projects`, `asOf`, `criteria`, `status` and `window` retain the 24h representation for older clients. Diagnostics count observations (including duplicate pool snapshots), not unique projects or users. They reveal no private identities.
- The thin 28px ribbon has accessible 1h/24h controls and remembers only the chosen viewing mode in the browser. The public selection stays independent of the active stream. Diagnostics update without rebuilding the moving slate. Inspection still pauses changes; keyboard, touch, Escape and reduced motion retain their prior behavior. Empty states distinguish collection, dated observations awaiting refresh, and a sample with no qualifying projects. The Radar heading/empty-state tooltip explains the admission gaps. Valid empty samples remain possible during an outage or when no project meets the thresholds; no placeholder token is promoted into a recommendation.

## Source research and limits

Rechecked primary [DEXScreener API documentation](https://docs.dexscreener.com/api/reference), [GMGN Agent API documentation](https://docs.gmgn.ai/index/gmgn-agent-api), and [FOMO's token-stat explanation](https://fomo.family/answers/how-to-read-token-stats). Existing DEX profile/update/takeover seeds and exact-contract batches provide documented public data and are the immediate reliable improvement. Listings, takeovers and volume are attention leads, not verified organic inflows.

The GMGN read-only adapter and explicit FOMO/GMGN page-research path from 0.3.7–0.3.8 are preserved. GMGN's documented API requires access/key configuration; it is still optional and off when unconfigured. No authenticated GMGN stream has been newly verified. FOMO's public page must actually expose the requested contract before its figures can be summarized. Prior tests found the supplied FOMO token identity unreadable and GMGN browsing access denied; this release does not bypass those restrictions or fabricate a continuous feed. Screenshots and language-model summaries remain separately dated observations, never contract clearance, precise candle histories or execution authority. The OpenAI audio key remains voice-only.
